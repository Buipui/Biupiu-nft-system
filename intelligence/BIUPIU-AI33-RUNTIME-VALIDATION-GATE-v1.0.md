## Objective
Move the AI-32 architecture-level contract into a controlled executable validation harness without silently treating simulated or AI-derived values as observed physical state.

## Execution contract
1. Load a task packet and evidence set.
2. Validate schemas and required provenance fields.
3. Run deterministic mathematical sanity checks.
4. Run a digital-twin/simulation adapter when an executable model is available.
5. Inject controlled faults.
6. Verify contradiction detection and state separation.
7. Re-run after remediation.
8. Record regression evidence.
9. Promote only if all required checks pass.

## State model
OBSERVED = measured by an external instrument or trusted runtime input.
COMPUTED = derived by deterministic calculation.
SIMULATED = generated by a model/digital twin.
INFERRED = model/AI inference requiring explicit provenance.
UNKNOWN = unavailable or unresolved.

No transition from COMPUTED/SIMULATED/INFERRED to OBSERVED is permitted without an external measurement record.

## Fault classes
- schema/input fault
- unit/dimension fault
- numerical instability
- model-contract mismatch
- contradictory evidence
- dependency/security fault
- provenance mismatch

## Promotion rule
AI-33 may become PROMOTION-READY only when executable evidence exists for the checks above. Repository documentation alone cannot mark runtime execution as PASS.
