## 1. Creative objective

Create original generative artwork inspired by documented ancient water-management principles and expressed through computational geometry. The visual language should combine archaeological/engineering structure with refined futuristic Biupiu geometry.

The artwork must not imply that the generated image is an exact archaeological reconstruction unless the underlying model has been independently validated.

## 2. Visual DNA

Core visual components:
- Flow-field lines representing water movement
- Terrain/elevation contours where reliable data are available
- Channel and reservoir geometry
- Radial and recursive structures
- Network intersections
- Parametric curves and surfaces
- Controlled symmetry/asymmetry
- Organic biological forms only where explicitly linked to the research concept

Avoid generic mystical/sacred-geometry imagery where it is not supported by the research source. Historical motifs should be used only where rights and provenance permit.

## 3. Generation stages

1. Select a documented ancient water-management reference.
2. Record source genealogy and evidence level.
3. Extract measurable geometry or construct clearly labelled modelling assumptions.
4. Build a terrain/flow abstraction.
5. Apply computational geometry transformations.
6. Generate multiple candidate outputs.
7. Select an original composition using documented criteria.
8. Record all parameters and the generation seed.
9. Export master artwork.
10. Calculate asset hash.
11. Create NFT metadata.
12. Calculate metadata hash.
13. Complete IP/licence review.
14. Approve minting only after the release checklist is complete.

## 4. Algorithm specification

**Algorithm ID:** FLOW-GEOMETRY-001  
**Initial version:** 0.1  
**Purpose:** Convert flow/terrain/network parameters into a generative visual composition.

Suggested pipeline:

`terrain/flow inputs → vector field → streamlines → geometric transformation → recursion/tessellation → composition → rendering`

The exact mathematical implementation remains a development task and must be recorded in source control before the final artwork is released.

## 6. Originality and source policy

The final artwork should be newly generated by Biupiu. Reference photographs, scans, maps, artworks, code, datasets and other third-party assets must not be incorporated merely because they are publicly accessible online.

For every external input record:
- source
- creator/rights holder where known
- licence
- permitted commercial use
- attribution requirement
- modification/derivative-work requirement
- date accessed
- role in the artwork

GitHub source code is subject to its repository's licence and is not automatically free for commercial reuse.

## 7. Evidence and interpretation

**Default evidence classification:** RECONSTRUCTED.

If the final artwork includes unverified interpretations, label the relevant component HYPOTHESIS or SPECULATIVE. Documented historical information should remain distinguishable from Biupiu artistic transformation.
