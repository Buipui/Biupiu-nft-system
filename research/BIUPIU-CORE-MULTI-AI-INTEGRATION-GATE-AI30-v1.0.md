## Scope

The Biupiu main branch now has a provider-neutral AI team architecture spanning:
OS, DMS, subsystems, simulators, configurators, MATH, physics, Digital Twin, intelligence, blockchain, provenance and repository governance.

## Core rule

No AI provider is the Biupiu authority by itself. Providers are specialist workers behind a common interface. The Biupiu Intelligence layer owns task identity, evidence state, validation, conflict handling, promotion and provenance.

## Interlinked team protocol

1. Orchestrator creates a Task ID.
2. Evidence layer creates an Evidence Set ID.
3. Specialist teams receive scoped work packages.
4. Teams may work in parallel.
5. Every output carries provider/model/version, source, licence state and confidence/evidence state.
6. Contradictions are retained and routed to a resolver.
7. MATH/PHYSICS validates quantitative claims.
8. SECURITY/EXTERMINATE checks code and dependencies.
9. SIMULATION/DIGITAL-TWIN checks system compatibility.
10. HUMAN/BIUPIU PROMOTION GATE authorises durable or irreversible changes.

## Code import boundary

Usable open-source components may be vendored only after exact-version licence/dependency/security/build checks. Provider APIs and proprietary implementations remain adapters. No private code, credentials, model weights or restricted assets are copied merely because an interface is public.

## System routing

AI -> OS/DMS -> capability graph -> MATH/PHYSICS -> SIMULATOR -> DIGITAL-TWIN -> CONFIGURATOR -> VALIDATION -> PROVENANCE -> BLOCKCHAIN.

Research and model updates flow back through the Intelligence learning registry as versioned evidence, not silent self-modification.
