# BIUPIU RESEARCH OPERATING PROTOCOL v2.0

**Date:** 15 September 2026  
**Status:** Active

## Core principle

**Ancient knowledge generates the question. Archaeology establishes the historical record. Anthropology explains human-material context. Science tests mechanisms. Engineering converts mechanisms into designs. Computation models and optimises them. Experiments decide what works. IP review determines what can be protected or commercialised.**

## Permanent source stack

1. Primary archaeology/history and original datasets.
2. JSTOR.
3. AnthroSource / American Anthropological Association.
4. ResearchGate and scientific/engineering literature.
5. Emerald Insight / Emerald Publishing.
6. Ancient texts and specialist textual scholarship.
7. Scientific primary datasets.
8. Patents and prior art.
9. Public/declassified engineering archives.
10. GitHub / BIUPIU CODEX and other openly licensed computational resources.
11. Biupiu computational validation.
12. Biupiu physical/experimental validation.

Controlled speculative sources may be used at the hypothesis-generation stage but never promoted to evidence merely through repetition.

## Standard research record

Every major discovery should be recorded as:

`Research ID → Source ID → Exact claim → Source genealogy → Department codes → Evidence status → Technical question → Computational model → Experimental test → IP/FTO status → Commercial/NFT relevance`

## Source-specific rules

### AnthroSource
Use for archaeology/anthropology, technology transmission, craft production, materiality, cultural ecology, human-material relationships and social organisation. Record DOI/stable URL and exact proposition. Do not infer engineering performance beyond the source.

### ResearchGate
Use for scientific/engineering discovery and author-accessible papers. Prefer DOI/publisher/institutional versions for final evidence. Record experimental conditions and limitations, not only headline numbers.

### Emerald Insight
Use for sustainability, water, agriculture, infrastructure, engineering management, optimisation and system-level implementation. Identify exact publication/DOI before treating an Emerald result as independent evidence.

### GitHub
Use for computational methods, code, algorithms, datasets, notebooks and reproducible engineering. Record repository, commit/tag, author, licence and dependencies. Public availability does not imply public-domain or commercial reuse rights.

### Patents
Record publication number, priority date, applicant, inventor, jurisdiction, legal status and relevant independent claims. Patent existence is not evidence of efficacy.

### Declassified documents
Use only lawfully public/declassified technical records. Treat them as historical engineering documentation requiring independent validation. Do not seek classified or restricted information.

## Computational gate

No AI optimisation should be used to compensate for an unvalidated physical model. The sequence is:

`baseline model → verification → validation → sensitivity/uncertainty → optimisation → surrogate/AI acceleration → experiment`

## Experimental gate

A simulation result is not a prototype result. A prototype result is not a validated commercial product. Preserve raw data, calibration, sample provenance, software version, parameters and repeatability information.

## Evidence statuses

- A — Directly demonstrated
- B — Strongly supported
- C — Plausible/incomplete
- D — Testable hypothesis
- E — Unsupported/contradicted
- M — Mythological/cultural
- S — Speculative/inspirational

## Repository correlation

All new records must be mapped into `research/BIUPIU-DEPARTMENT-INDEX.md` and, where relevant, `research/BIUPIU-DEPARTMENT-MAP.md`, `research/SOURCE-TO-DEPARTMENT-CROSSWALK.md`, and a CODEX queue.

Aerospace and mobility work remains civilian/dual-use and efficiency/materials focused. No classified/restricted or weapon-design information is incorporated.
