## Purpose
Computational geometry is a hard, machine-readable behavioural feature layer for the multidimensional information archive and AI learning system. Shapes are represented by observable relationships, transformations and invariants, not only by images.

## Behaviour model
The baseline covers DISTANCE, CONTAINMENT, INTERSECTION, ADJACENCY, SYMMETRY, TOPOLOGY, CURVATURE, TRANSFORM, SCALE, FLOW, COLLISION and NETWORK behaviours.

Hard fields include coordinate frame, units, relations, invariants, numerical tolerance, transformations, behavioural tests, provenance and evidence state.

## Archive dimensions
Geometry is inserted as an explicit computational behaviour dimension alongside identity, knowledge, mathematics, physics, quantum, computation, Digital Twin, Federation, evidence, temporal, security/trust and blockchain.

## Search hard-element contract
Every authorized search, harvest, retrieval or information run MUST carry a geometry-behaviour envelope. When geometry is relevant it MUST contain intent, coordinate frame, units, relations, invariants, tolerance, transformations, behavioural tests, provenance and evidence state. When geometry is not relevant, the envelope MUST still be present with applicability=NONE.

This is a metadata requirement, not permission to invent a geometric interpretation.

## AI learning rule
Learning preserves input -> geometric representation -> behaviour features -> invariant/test result -> output -> evidence -> provenance -> regression. Repeated correlation is not automatically a physical law.
