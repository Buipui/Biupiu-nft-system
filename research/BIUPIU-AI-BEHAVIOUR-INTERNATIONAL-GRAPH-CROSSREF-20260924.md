## 3. AI behaviour state model

The audit consolidates the following machine-readable behavioural distinction:

OBSERVE -> CLASSIFY -> INFER -> PROPOSE -> SIMULATE -> VALIDATE -> AUTHORISE -> EXECUTE

Authority remains:

HUMAN RELEASE -> CORE OS/DMS -> DOMAIN OWNER -> NATIVE INTELLIGENCE -> FEDERATION -> ADAPTER/PROVIDER -> EXTERNAL REFERENCE

The following are not equivalent: inference ≠ fact; model output ≠ measurement; simulation ≠ physical validation; external source ≠ authoritative implementation; source compatibility ≠ runtime capability; optimisation candidate ≠ measured optimisation improvement; quantum-inspired result ≠ QPU result.

## 6. Behaviour fault classes added to the audit vocabulary

1. AUTHORITY_LEAK — proposal/inference incorrectly becomes execution authority.
2. EVIDENCE_LEAK — unsupported output is represented as established fact.
3. PROVENANCE_BREAK — source/derivation cannot be traced.
4. MODEL_FACT_COLLAPSE — model/simulation result presented as measurement or physical truth.
5. RUNTIME_EQUIVALENCE_ERROR — source compatibility treated as runtime capability.
6. QUANTUM_CLAIM_LEAK — simulator/quantum-inspired result represented as QPU evidence or advantage.
7. OPTIMISATION_CLAIM_LEAK — candidate optimisation represented as measured improvement without matched execution.
8. GRAPH_EDGE_UNSUPPORTED — graph relationship has no source or explicit inference basis.
9. LICENCE_AUTHORITY_LEAK — external material treated as executable despite unresolved licence/provenance.
10. HISTORICAL_RECORD_MUTATION — learning/audit history silently rewritten.
