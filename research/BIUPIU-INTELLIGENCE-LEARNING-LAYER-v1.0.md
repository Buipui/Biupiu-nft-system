# Biupiu Intelligence — Learning Layer v1.0

**Date:** 19 September 2026  
**Status:** Core architecture / repository implementation foundation

## Purpose

The Learning Layer is the persistent feedback system around the Biupiu Intelligence Layer. It allows the system to learn from **versioned evidence, experiments, failures, simulations, human decisions and repository changes** without silently rewriting historical knowledge.

It is distinct from model training. A model may change; the learning record remains a durable lineage of what was observed, what was proposed, what was tested and what changed.

## Core loop

`SOURCE → CLAIM → HYPOTHESIS → MODEL → SIMULATION → EXPERIMENT → RESULT → FEEDBACK → LEARNING RECORD → NEXT CANDIDATE`

Repository maintenance adds a second loop:

`CODE/DOC → TEST → FAILURE/DIFF → FIX → REGRESSION RESULT → NEW VERSION → LEARNING RECORD`

## Learning record

Each learning event should retain:

- stable `learning_id`
- object/experiment/repository target
- input references and source IDs
- evidence state
- prior version
- resulting version
- model/provider version where applicable
- observed outcome
- expected outcome
- error/uncertainty where measurable
- human decision or approval state
- next action
- provenance hash
- timestamp
- parent event/checkpoint

## Knowledge classes

- **FACT** — directly supported source or measurement.
- **MODEL_OUTPUT** — generated by a computational/model process.
- **HYPOTHESIS** — proposed and testable.
- **SIMULATION_RESULT** — computational result, not physical validation.
- **MEASUREMENT** — recorded physical/device observation.
- **INTERPRETATION** — reasoned explanation linked to evidence.
- **FAILURE** — negative/inconclusive result retained for learning.
- **REPOSITORY_CHANGE** — code/config/documentation change with test status.

The intelligence layer must never convert a lower-confidence class into FACT merely because a model repeats it.

## Candidate selection

Candidate experiments or research actions may be ranked internally using measurable signals such as uncertainty reduction, information gain, model disagreement, sensitivity, feasibility and Pareto relevance. These are decision-support signals, not scientific proof.

## Memory policy

Old and new records are both valuable during the learning phase.

- ACTIVE — current implementation or knowledge.
- EXPERIMENTAL/HISTORICAL — retained because it may contain useful learning evidence.
- ARCHIVED — superseded but intentionally preserved.
- DEPRECATED — no longer recommended for new work, but retained for lineage.

A duplicate-looking file must not be deleted solely because a newer file exists. Deduplication requires content comparison, provenance review and supersession evidence.

## Human control

Durable promotion, deletion, public release, IP transition, production deployment and blockchain anchoring require an explicit approval gate. AI suggestions remain suggestions until accepted.

## Privacy

Training/learning records should default to off-chain and private/local storage. Blockchain is used only for approved cryptographic commitments/checkpoints.

## Implementation boundary

The repository implementation provides deterministic schemas, lineage and audit primitives. It does not claim that a particular AI model is autonomous, self-improving or scientifically validated.
