# BIUPIU Deep Search + Substitute Resource Research Protocol v1.0

Date: 20 September 2026
Status: IMPLEMENTED — repository research/governance layer
Purpose: Establish a repeatable recovery protocol for blocked, missing, incompatible or unusable software/research resources.

## 1. Trigger

PROBLEM -> REPRODUCE -> ISOLATE -> CLASSIFY -> DEEP SEARCH -> SUBSTITUTE -> VALIDATE -> INTEGRATE -> LEARN -> INDEX

A failed search does not close the requirement; it opens a governed substitution track.

## 2. Deep-search hierarchy

1. Primary owners / R&D companies / industrial developers — official product documentation, developer portals, public SDKs, research programmes, technical papers, public sample code and explicitly shared assets.
2. Universities / government laboratories / research institutes — research software, reference implementations, datasets, theses, technical notes and reproducible prototypes.
3. Open-source foundations / public repositories — mature implementations, test suites, libraries, examples and interoperability adapters.
4. Standards and interoperability projects — open specifications, schemas, protocols, reference models and conformance tests.
5. Community mirrors / derivative repositories — discovery and comparative evidence only until provenance and licence are independently verified.

Shared proprietary asset means an asset lawfully made available under a developer agreement, purchased/commercial licence, academic/research licence, partner agreement, public SDK programme or other explicit permission. No DRM, authentication, paywall, NDA, licence-control or access restriction may be bypassed.

## 4. Resource trust classes

| Class | Meaning | Initial treatment |
|---|---|---|
| R0 | Primary official source / owner | Reference; licence review required |
| R1 | Explicitly licensed open source | Candidate dependency after licence/security review |
| R2 | Explicit commercial/academic/shared proprietary access | Library record + access/licence conditions; no redistribution assumption |
| R3 | University/lab research prototype | Research/reference; maturity and licence review |
| R4 | Community repository / derivative | Discovery only until provenance/rights verified |
| R5 | Unknown rights / ambiguous origin | Do not integrate; retain only as a blocked reference record |

## 5. Licence/security gate

Every candidate receives: SOURCE_ID, OWNER, VERSION, COMMIT, LICENCE, COMPONENT-LICENCES, ASSET-RIGHTS, DEPENDENCIES, SECURITY-STATUS, EXPORT/ACCESS-NOTES, INTEGRATION-MODE

No source becomes Biupiu-owned IP merely because it is indexed.

Unknown or incompatible rights route to one of: isolated external service, interface-only adapter, paid/shared licence acquisition, substitute resource, or reference-only library entry.

## 6. Substitute selection

Select the smallest substitute that closes the missing capability without weakening the system boundary.

Priority: same-interface -> same-behaviour -> same-domain -> cross-domain analog -> new Biupiu implementation

Record what failed, why it failed, and what substitute was chosen so future agents can avoid repeating the same dead end.

## 7. Cross-disciplinary Digital Twin routing

The Digital Twin acts as a capability-fit engine, not an authority to promote code.

RESOURCE -> CAPABILITY GRAPH -> DIGITAL TWIN FIT -> DEPARTMENT ROUTE -> SIMULATOR/CONFIGURATOR ROUTE -> VALIDATION QUEUE

The twin evaluates interfaces/protocols, data schemas, units/coordinates, model fidelity, compute requirements, language/toolchain, licence restrictions, safety/security constraints, testability and target physical asset/system.

## 8. Integration destinations

- Biupiu OS: ABI/HAL, device services, transport, scheduling, machine capability and platform services.
- Biupiu DMS: provenance, inventory, dependency records, access control, workflow and deployment metadata.
- Biupiu Intelligence: evidence, terminology, provenance, licence facts, failure patterns and reusable retrieval rules.
- Simulators: vehicle, aerospace, marine, robotics, agriculture, materials, multiphysics and infrastructure.
- Configurators: CAD, material, colour, machine, system and product configuration.
- Biupiu World: OpenUSD/3D scene, asset metadata, interactive twins, robotics and environmental simulation.
- Departments: agriculture, biotechnology, food, textiles, composites, energy, photonics, electromagnetics, automotive, aerospace, marine, biomedical, robotics, manufacturing, geospatial and research/IP.

## 9. Machine-learning learning rule

The learning layer stores process evidence, not just search results.

problem -> source candidates -> rejection reasons -> licence/security findings -> substitute -> tests -> outcome -> reusable routing rule

Training records must preserve original-language terms, source identity, source class, licence class, evidence quality, failure signature, substitute signature, department fit, simulator/configurator fit and validation outcome.

## 10. Promotion boundary

DISCOVERY != VALIDATION != INTEGRATION != PROMOTION

No executable external asset is promoted because of popularity, source count, translation quality, repository stars or vendor prestige.

## 11. Gate completion definition

A recovery gate is complete only when:
1. the blocker is reproduced or bounded;
2. deep multilingual search has been attempted;
3. at least one legal candidate or documented substitute exists, or the requirement is explicitly marked unresolved;
4. provenance/licence/security metadata are stored;
5. the candidate is mapped to affected twins/departments/simulators;
6. tests or explicit runtime evidence are captured where executable integration is claimed;
7. the main indices and Intelligence learning records are synchronized.

Current gate state: Protocol implemented; current resource harvest registered separately; executable integration remains individually gated.
