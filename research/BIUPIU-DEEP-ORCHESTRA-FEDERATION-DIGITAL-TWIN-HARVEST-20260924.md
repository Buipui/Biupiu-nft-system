## New external knowledge harvested

### Digital Twin standardisation and composition
1. ISO 23247-2 defines a Digital Twin manufacturing reference architecture with domain/entity and functional views.
2. ISO 23247-4 defines technical requirements for information exchange between user, service, access and proximity networks.
3. ISO 23247-6:2026 adds Digital Twin composition guidance and explicitly distinguishes integrated, unified and federated composition. It treats independent twins as composable units and addresses communication, aggregation and interoperation.
4. NIST's current Digital Twin standardisation work identifies interoperability, common terminology/reference models, modularity, reusability and trustworthiness as scaling requirements.
5. NIST's 2026 Digital Twin workshop report highlights interoperability, verification/validation/uncertainty quantification (VVUQ), cybersecurity and workforce readiness as continuing barriers.

### Semantic interoperability
NIST work on machine-readable semantic models reinforces the Biupiu rule that Digital Twin metadata must be machine-readable, semantically linked and suitable for heterogeneous system integration.

### Hybrid Digital Twin
Recent 2026 research supports combining physics-based models with data-driven/ML components for evolving nonlinear systems. Biupiu adopts this only as a reference architecture: physics/model assumptions remain explicit, ML remains bounded and evidence-gated, and simulation output is not physical truth.

## Architecture updates

### Digital Orchestra
The event envelope is extended to preserve:
event_id; parent_task_id; correlation_id; source; target/authority owner; schema_version; timestamp; evidence_state; validation_state; provenance_refs; source_commit; build_state; test_state; rollback_ref; payload_hash.

Orchestra remains coordination authority only. It cannot promote external knowledge, alter canonical subsystem authority, or convert simulation into physical truth.

### Federation
Added source gates:
- F26 Digital Twin composition: composition mode, canonical owner, contextual parent, interoperability, provenance, regression.
- F27 Digital Twin VVUQ: model assumptions, uncertainty, validation method, correlation state, evidence state, rollback.
- F28 adaptive heterogeneous execution: capability discovery, runtime version, resource state, acceleration policy, fallback policy, telemetry, regression.

These gates are source-registered; they are not marked VERIFIED without explicit evidence.

### Digital Twin
Twin composition now follows:
DISCOVER -> IDENTIFY OWNER -> DEFINE CONTEXT/PARENT -> NORMALISE SEMANTICS -> COMPOSE -> OBSERVE -> VALIDATE/VVUQ -> REGRESSION -> LEARN -> GOVERNED PROMOTION.

Composition modes are represented as integrated, unified or federated. Linked does not mean merged.

### Learning
The passive-learning rule is retained:
PASSIVE -> OBSERVE -> NORMALISE -> COMPARE -> SCORE INFORMATION/UNCERTAINTY/RESOURCE VALUE -> STORE EVIDENCE -> ACTIVE VALIDATION WHEN JUSTIFIED -> REGRESSION -> PROMOTION.

Learning cannot activate expensive hardware, alter authoritative production behaviour, or bypass authority.

### Heterogeneous execution
Execution selection remains:
portable CPU/software -> vector/GPU/NPU/accelerator -> quantum simulation candidate only when evidence justifies escalation.

De-escalation and fallback are first-class states. Optimisation remains subordinate to SECURITY -> CORRECTNESS -> DETERMINISM -> AUTHORITY -> RESOURCE POLICY -> PERFORMANCE.
