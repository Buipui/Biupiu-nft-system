# Biupiu Multi-AI Architecture Builder v1.0
Gate: AI-NATIVE-01
Status: REGISTERED + IMPLEMENTED / HOST VERIFICATION PENDING

## Objective
Provider-neutral multi-agent architecture building that harvests existing Biupiu systems before creating new components, separates specialist roles, preserves failures, and prevents AI suggestions from becoming authoritative OS state without verification.

## Revised execution protocol
HARVEST -> MAP -> CHALLENGE -> PROPOSE -> IMPLEMENT -> VERIFY -> REGRESS -> AUDIT -> PROMOTE

HARVEST searches repository history and approved resource registries for reusable code, contracts, tests, documentation, algorithms and failures.
MAP records ownership, authority, dependencies and affected gates.
CHALLENGE requires independent architecture, research, security, numerical and integration checks.
PROPOSE creates an evidence-backed plan without mutating authoritative state.
IMPLEMENT applies the smallest compatible change with provenance.
VERIFY executes deterministic tests and available CI or host evidence.
REGRESS checks dependent systems and retains failure evidence.
AUDIT checks provenance, licensing, security and unresolved conflicts.
PROMOTE updates architecture/index records only after verification.

## Specialist roles
HARVESTER, ARCHITECT, RESEARCHER, IMPLEMENTER, VERIFIER, SECURITY, INTEGRATOR, AUDITOR.

Roles may be fulfilled by one or multiple model providers. Role separation is mandatory even when one provider performs several roles.

## Conflict protocol
Classify dependency, interface, schema, version, runtime, data, provenance, licence, resource, logic, numerical, integration or unknown conflicts. Never silently overwrite a conflict.

## Harvesting rule
REUSE BEFORE REBUILD. A new module records why an existing module, contract or test could not satisfy the objective before duplicating functionality.

## Authority
AI proposal -> OS validation -> authoritative state.
No AI role can bypass OS controls, release gates, security boundaries, licence review or human release authority.

## Mini OS / Main OS boundary
The native mini-system is the controlled proving ground. Patterns are promoted into the Main OS only through evidence-backed compatibility and regression gates; no blind copying is permitted.
