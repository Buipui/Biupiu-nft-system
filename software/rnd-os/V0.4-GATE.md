# Biupiu R&D OS — v0.4 Gate

## Objective

Move tenant isolation from design primitives into a reusable datastore boundary while preserving the distinction between development JSON storage and verified PostgreSQL production infrastructure.

## Implemented

- tenant-aware record filtering
- authenticated-organisation scope primitive
- cross-organisation access rejection
- minimum-role write enforcement
- automated tenant isolation tests
- PostgreSQL adapter and migration runner from the preceding gate

## Runtime target

AUTHENTICATE → RESOLVE ORGANISATION → SCOPE DATA → AUTHORISE ROLE → APPLY DOMAIN RULES → AUDIT

## Verification boundary

The tenant-store tests are deterministic unit tests. They do not constitute proof of a live PostgreSQL deployment or full API security.

The next verification requirement is API-level enforcement across reads, writes, transitions, relationships, package operations and audit events, followed by a real PostgreSQL integration environment.

## Status

**v0.4 implementation gate: OPEN**

Production SaaS, regulated laboratory use, security certification and successful live PostgreSQL operation remain unclaimed until independently verified.
