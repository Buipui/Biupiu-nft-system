# Biupiu R&D OS v0.3 — Gate Specification

## Gate objective

Move the MVP from architecture/scaffolding toward a controlled multi-tenant runtime while keeping PostgreSQL, authentication and security explicitly non-production until independently verified.

## Implemented in this gate

- organisation-scoped identity primitives
- role hierarchy and permission checks
- tenant-scope enforcement primitives
- datastore abstraction retained between API and persistence
- PostgreSQL schema remains the production target
- explicit production-security boundary
- CI remains the required automated verification path

## Required v0.3 runtime path

`REQUEST → AUTHENTICATE → RESOLVE ORGANISATION → AUTHORISE ROLE → LOAD TENANT DATA → APPLY DOMAIN RULES → AUDIT → RESPOND`

## Security rules

1. Never trust a client-supplied organisation identifier.
2. Resolve organisation scope from the authenticated principal.
3. Reject cross-organisation reads and writes.
4. Enforce minimum roles at the API boundary.
5. Store token hashes rather than reusable bearer secrets.
6. Record security-relevant actions in the audit stream.
7. Do not treat the development JSON store as production-safe persistence.

## Exit criteria

- tenant-isolation tests
- role-permission tests
- authentication/session tests
- PostgreSQL integration tests
- migration test from JSON seed package
- CI passing on the gate commit
- security review before production deployment

## Status

**v0.3 engineering gate opened.**

Production SaaS, regulated laboratory use and security certification remain unclaimed until the exit criteria are independently demonstrated.
